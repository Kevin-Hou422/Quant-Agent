## 改了什么

`BacktestEngine.run()` 里这一行：

```python
# 旧
adj_weights = self._liq.apply(weights, adv_usd_df, self.initial_capital).to_numpy()
```

换成与执行层**同一份原语**的逐日撮合：

```python
# 新
cap_trade_mat = adv_usd * self.params.max_participation_pct / self.initial_capital
prev_filled = np.zeros(N)
for t in range(T):
    fr = simulate_partial_fills(prev_filled, tgt_arr[t], cap_trade_mat[t],
                                max_net=self.max_net)
    adj_weights[t] = fr.filled_w
    prev_filled = fr.filled_w
```

### 旧实现错在哪（两处，不是一处）

**① 口径错：裁的是持仓，而流动性约束的是成交量。**
`LiquidityConstraint.apply` 对整个 T×N **目标持仓**矩阵做 water-filling。
但 ADV 限制的是「今天能成交多少」。一只昨天已经持有 0.5、今天目标还是 0.5 的票
**根本不需要交易**，却照样被 ADV 上限削掉持仓。

**② 会再分配：A 买不到就多买 B。**
water-filling 把被削掉的额度摊给其他票：`[0.9, -0.1]` 落账成 `[0.01, -0.99]` ——
10% 的对冲腿变成 99% 的方向性空头。券商不会这么干。
（构建层用 water-filling 是对的：容量不足就换个票装，产出的是**新目标**并要重新过风控。
执行层不行 —— 用户决定 #1。）

执行层已于 2026-09-18/19 改为 `simulate_partial_fills`，回测一直没动，
于是两个引擎在限流场景下语义分家。原有的 `test_replay_matches_backtest_engine`
用的是成交量充足的数据（上限不绑定），**看不见**这个分叉。

### 新语义是路径依赖的

今天成不了的量既不会凭空消失，也不会被摊给别人，而是**留到以后接着成交**。
持仓向目标逐日逼近，而不是一步到位或被永久削平。

## 差异怎么解释

**只有限流真正绑定时才有差异**，这正是预期：改的是"流动性不足时怎么办"，
不绑定时两种算法本就该给同一个答案。两档不绑定场景**逐位相同**是重要的对照 ——
它证明改动打在点子上，不是无差别地改了所有东西。

绑定场景的三个变化互相印证，指向同一个机制：

**敞口上去了（0.11 → 0.55）。** 旧实现把**持仓**硬压在 ADV 上限附近，于是无论
持有多久，敞口永远上不去。新实现限制的是**每天的成交量**，持仓可以跨日累积 ——
第一天买不到的，第二天接着买。这才是真实世界的样子：流动性差不等于永远只能持有一点点，
而是**建仓慢**。

**换手上去了（3.7 → 12.9）。** 旧实现把目标削得极平，日间目标变动也跟着被削平，
于是几乎不换手。新实现真的在逐日调仓。

**收益变差了（-0.05% → -2.88%）。** 这是前两条的直接后果：真的持有了仓位，
就真的承担了盈亏；真的换手了，就真的付了成本。

**方向是"变差"，这一点很重要。** 旧实现在流动性差的标的上**同时低估了敞口和成本**，
让一个本该"慢慢建仓、付不少成本"的策略看起来像"几乎没持仓、也几乎没亏"。
那是**对自己有利的偏差** —— 回测显示无害，实盘才发现既有敞口又有成本。
修正之后回测更难看，但更接近能兑现的东西。

## 谁受影响

- **生产日循环**：不受影响。`daily_trading_loop` 走的是 `PaperBroker`，
  那一侧 2026-09-18/19 就已经是新语义。
- **历史回测数字**：**流动性受限的标的/时段上会变差**。此前存档的回测结论，
  凡是涉及小市值、低成交量、或大 AUM 相对标的容量偏大的，都应当按新引擎重跑。
- **上限不绑定的回测**：逐位不变，无需重跑。

## 这件事如何被守住

- `test_known_defects.py::test_the_two_engines_agree_when_liquidity_binds`
  —— 在**限流真正绑定**的数据上对账两个引擎，1e-9。这条原本是 xfail，
  引擎统一后转正。
- ⚠️ 它**不是**「两边一样就算对」。正确性由各自的独立断言守：
  执行侧见 `test_paper_broker_accounting.py` 的 `TestGrossExposureFollowsTheTarget`
  与 `Test*PartialFill*`；构建层见 `test_partial_fill_semantics.py`（52 条）。
  两者都对**且**彼此一致，才算完成。
- `max_net` 两个引擎同款默认 `None`（明确选择不限制）。生产链路由
  `RiskLimits.max_net` 显式传入 —— 配置缺失不得静默降级为 None。
